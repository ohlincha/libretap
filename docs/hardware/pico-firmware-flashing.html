Pico firmware: flashing

Puts LibreTap's firmware, USB Sniffer Stream, on the Raspberry Pi Pico of the USB sniffer. Takes a minute; nothing to install. Works the same on Windows, macOS and Linux.

You need

  • The Pico (RP2040; Pico 2 and Pico W are not supported). It may already be wired into the sniffer cable.
  • A micro-USB data cable. Some cables only charge: with those, no drive appears.
  • The firmware file UsbSnifferStream.uf2: on the LibreTap releases page (github.com/ohlincha/libretap/releases, from version 0.1.3) or directly:
    https://github.com/ohlincha/libretap/raw/main/firmware/pico-usb-sniffer/bin/UsbSnifferStream.uf2

1. Start the Pico in its loader

2. Copy the file

Windows (10 and 11)

  1. The drive RPI-RP2 opens in Explorer (otherwise open it under This PC).
  2. Drag UsbSnifferStream.uf2 from Downloads onto it.
  3. The window closes as the Pico restarts. The Pico is now a serial port (COM3, COM5, …); Windows needs no driver.

macOS

  1. RPI-RP2 appears on the desktop and in Finder's sidebar.
  2. Drag UsbSnifferStream.uf2 onto it.
  3. Some macOS versions then report an error or "disk not ejected properly". If the drive has disappeared, the copy worked; dismiss the message.
  4. If Finder refuses to copy: Terminal, then cp -X ~/Downloads/UsbSnifferStream.uf2 /Volumes/RPI-RP2/

The Pico is then a serial port named /dev/cu.usbmodem….

Linux

  1. The desktop mounts RPI-RP2 (in the file manager's sidebar). Drag the file onto it.
  2. Or in a terminal: cp ~/Downloads/UsbSnifferStream.uf2 /media/$USER/RPI-RP2/ (the mount point varies: /run/media/$USER/RPI-RP2 on some systems).
  3. The Pico is then /dev/ttyACM0 (or ACM1, …). Serial ports need the dialout group: if LibreTap does not list the sniffer, run sudo usermod -aG dialout $USER and log out and in.

3. Check that it worked

  1. Unplug and replug the Pico (without BOOTSEL). Its LED blinks slowly.
  2. Start LibreTap. Connections shows USB sniffer ready (Pico on …, USB Sniffer Stream). It records continuously, like the other sources.
Check. The text says USB Sniffer Stream. If it says the sniffer "captures in short pieces", the Pico still has the original usb-sniffer-lite firmware: flash again.

Going back

To return to the original usb-sniffer-lite firmware, copy its UsbSnifferLite.uf2 (github.com/ataradov/usb-sniffer-lite, folder bin) the same way. The wiring is the same for both. LibreTap works with either; with usb-sniffer-lite it records in short pieces (Record, one action, Stop).

Troubleshooting

SymptomLikely causeAction
No RPI-RP2 drive appearscharge-only cable; BOOTSEL released too earlyAnother micro-USB cable. Hold BOOTSEL until the cable is fully in.
Drive appears but the copy fails (macOS)Finder's copyTerminal: cp -X as above.
Copy worked, the drive is back againBOOTSEL still held, or a wrong fileRelease BOOTSEL; use UsbSnifferStream.uf2 from the link above.
LibreTap does not list the Pico (Linux)serial port permission; ModemManager probing the portdialout group (above). Optional: the udev rule firmware/pico-usb-sniffer/bin/90-usb-sniffer-lite.rules into /etc/udev/rules.d/.
LED does not blinkfirmware not runningReplug without BOOTSEL; flash again.

USB Sniffer Stream is untested on a real Pico so far; report problems at github.com/ohlincha/libretap/issues.
