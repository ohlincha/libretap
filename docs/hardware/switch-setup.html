Ethernet capture: switch setup

Lets LibreTap see the network traffic between an instrument and its PC, using a switch with port mirroring (TP-Link TL-SG105E). The instrument and the PC notice nothing; the laptop only listens.

An ordinary switch sends the laptop only its own traffic and broadcasts, so plugging the laptop into the lab network shows nothing useful. A switch with port mirroring copies the traffic of chosen ports to one more port. Unmanaged switches (most office switches, e.g. TL-SG1008D) cannot do this.

You need

  • TP-Link TL-SG105E (or another switch with port mirroring) and its power adapter.
  • Three network cables: instrument, instrument PC, laptop.
  • A laptop with an Ethernet port (or a USB–Ethernet adapter) and LibreTap, which uses Wireshark's dumpcap. Wireshark or tcpdump alone also work.

1. Set up the switch (once)

  1. Power the switch and connect only the laptop to it. The switch's address is 192.168.0.1.
  2. Give the laptop's Ethernet port the fixed address 192.168.0.10, mask 255.255.255.0, no gateway.
    Windows: Settings ▸ Network ▸ Ethernet ▸ IP assignment ▸ Edit ▸ Manual, IPv4.
    macOS: System Settings ▸ Network ▸ Ethernet ▸ Details ▸ TCP/IP ▸ Configure IPv4: Manually.
    Linux: sudo ip addr add 192.168.0.10/24 dev <interface>
  3. Open http://192.168.0.1 in a browser and log in as admin / admin. Set a new password when asked and write it on the switch.
  4. Monitoring ▸ Port Mirror: enable mirroring. Mirroring port = 5 (the laptop). Mirrored ports = 1 and 2, each with Ingress and Egress. Apply.
  5. System ▸ Save Config. Without this the setting is lost when the switch loses power.

The laptop's fixed address is only needed for this; set it back to automatic afterwards if you like.

2. Cable it

PortConnectRole
1Instrumentmirrored (ingress + egress)
2Instrument PCmirrored (ingress + egress)
3, 4nothing—
5Laptopmirroring port: receives the copies
  1. Unplug the cable between the instrument and its PC and put the switch in between (Figure 1). If the instrument and PC are on the lab network through another switch, plug that switch's cable into port 3 instead of leaving it empty; it is then not mirrored.
  2. Check that the vendor software still connects to the instrument. Instrument and PC keep their own addresses and settings; nothing changes on the instrument PC.

3. Capture

LibreTap: tick Ethernet under Connections, choose the laptop's Ethernet port, then Record. Note what you do in the vendor software as you go (marks), so the traffic can be matched to the screen.

Without LibreTap: Wireshark on the Ethernet port, saved as pcapng; or on Linux and macOS:

sudo tcpdump -i <interface> -s 0 -w eth_$(date +%Y%m%d_%H%M%S).pcap
Check. You see packets between two addresses that are not the laptop's: the instrument and its PC.

Troubleshooting

SymptomLikely causeAction
Only broadcasts (ARP, DHCP, NetBIOS, mDNS)mirroring off, or not saved and the switch was unpluggedRepeat steps 4 and 5 of part 1.
Nothing at allwrong interface; laptop not in port 5Pick the Ethernet port in LibreTap; check the cable is in port 5.
Cannot open http://192.168.0.1 againlaptop has no 192.168.0.x address; other devices plugged inLaptop alone on the switch, address 192.168.0.10 (part 1, step 2).

Password lost: hold the switch's Reset button about 5 s with power on (back to admin / admin, no mirroring). Menu names are from TP-Link's documentation and not yet checked on a real TL-SG105E; other firmware versions may name them differently. Untested on real instruments.
